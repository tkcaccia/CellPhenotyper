# Learned-model provenance

Every completed report rebuild writes:

- `00_execution/model_inventory.json`: complete machine-readable registry, per-run instances, checkpoint digests, missing fields and release blockers.
- `00_execution/model_inventory.tsv`: one-row-per-component review table.

The inventory combines a reviewed static registry in `resources/model_registry.json` with runtime metadata emitted inside the same container process that loads each model. Checkpoint SHA-256 values are streamed from disk and do not duplicate weights or load them into RAM. Hugging Face stages record the resolved cache snapshot commit, not merely a mutable requested revision such as `main`.

`release_ready=true` requires every learned component used by that run to have all of the following:

1. Source repository.
2. Immutable resolved revision or versioned artifact record.
3. SHA-256 for the loaded checkpoint or installed model bundle.
4. Verified checkpoint license.
5. Declared training domain.
6. Runtime cache path.

A technically successful run may therefore have a failing `model_provenance` quality signal. This does not retroactively invalidate its numerical files, but it prevents that run from being described as fully reproducible or release-ready.

## Upstream terms requiring attention

| Component | Recorded upstream terms | Current release interpretation |
|---|---|---|
| GrandQC | [CC BY-NC-SA 4.0](https://github.com/cpath-ukk/grandqc#license) | Verified non-commercial/share-alike terms. |
| StarDist | [BSD-3-Clause software](https://github.com/stardist/stardist) | The exact pretrained `2D_versatile_he` checkpoint terms still require an explicit upstream statement; software licensing alone is not treated as checkpoint licensing. |
| HoVer-Net MoNuSAC | [MIT software](https://github.com/vqdang/hover_net) | The exact MoNuSAC checkpoint terms still require verification. Its four positive cell classes are not an exhaustive nucleus ontology. |
| CellViT++ HIPT | [component-specific license](https://github.com/TIO-IKIM/CellViT-plus-plus/blob/main/LICENSE) | HIPT-derived and original components include Commons Clause restrictions in addition to Apache-2.0 terms. |
| GigaTIME | [repository license file](https://huggingface.co/prov-gigatime/GigaTIME/blob/main/LICENSE) | The restrictive research-only license file conflicts with the `apache-2.0` model-card metadata. Release use remains blocked until the provider resolves or clarifies that conflict. |
| UNI2-h | [CC BY-NC-ND 4.0 gated terms](https://huggingface.co/MahmoodLab/UNI2-h) | Verified gated, non-commercial academic-use terms; checkpoint redistribution is prohibited. |
| MedSAM | [Apache-2.0 software](https://github.com/bowang-lab/MedSAM) | The downloaded ViT-B checkpoint terms still require a separately verified statement. |
| TITAN | [CC BY-NC-ND 4.0 gated terms](https://huggingface.co/MahmoodLab/TITAN) | Verified gated, non-commercial academic-use terms; the resolved snapshot commit is recorded even when `main` was requested. |
| PathoFMPred | Private installed package | Package version, installed serialized model databases, `DESCRIPTION`, `NAMESPACE`, declared license and source URL are recorded. Missing private source or license metadata remains a release blocker. |

The registry intentionally uses `null` or a blocking status when evidence is unavailable. Do not replace these with assumptions inferred from a related software repository, paper or dataset.

## Legacy outputs

Runs produced before this contract usually contain model names and selected settings but not immutable checkpoint evidence. Rebuilding their execution report will identify the learned stages as `partial`; it will not claim hashes for files that were never retained locally. A manuscript archive should be generated by a new run under the instrumented wrappers.
